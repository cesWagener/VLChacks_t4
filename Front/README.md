# Front: Clients menu

The advisor's **Clients** screen for the Sherpas challenge: the book of families after the plan is delivered. It has search (3 letters), a wealth filter, a sector-exposure filter, and filters that stay applied across reloads and visits. The full requirements are in [`client-menu-frontend-spec.md`](client-menu-frontend-spec.md).

Clicking a family opens **its own page** (`/clients/:id`): a **proposed message** from the advisor on top, then the family's plan laid out like the Sherpas shared plan (score, summary, retirement and goals with a net worth chart, assets, debt, savings and expenses, protection, investment analysis).

The book holds exactly the **four case families** from [`../cases`](../cases): Timothy & Melanie Weah, Michael Carter, Daniel & Emily Johnson and Samantha Lewis. No families are simulated.

## Run it

Needs Node 22 or later.

```bash
cd Front
npm install
npm run dev        # opens http://localhost:5173/clients
```

Other commands:

| Command | What it does |
|---|---|
| `npm run data` | Rebuilds `public/clients.index.json` and `public/plans/<id>.json` from the four folders in `../cases` |
| `npm test` | Logic checks against the real cases (spec Appendix E) and the proposed messages |
| `npm run build` | Type-checks and builds to `dist/` |

## Stack

React 18 + TypeScript + Vite, plain CSS with the spec's design tokens (§8). No state library and no routing library.

## Code map

```

  lib/router.ts           /clients and /clients/:id
  lib/format.ts           money, percentages, labels
  components/             ClientSearch, WealthFilter, SectorFilter, FilterChips, ClientTable, EmptyState

```

The client list currently comes from static JSON built from `cases/`. To serve it from elsewhere later, change `src/lib/clientsSource.ts` so it returns the same `ClientSummary[]`. The UI does not change.

## Proposed message

Each family's page opens with a message from the advisor (David), drafted from that family's own plan data. It is generated by rules in `src/lib/message.ts`, not by a language model, so every sentence traces back to a number in `cases/`.

- **Tone follows the situation.** *Supportive* when the score band is critical or vulnerable: it starts with what the family does well, explains the hardest points plainly, says it is not their fault, and suggests one small first step with no pressure. *Steady* for a stable band, or when a good score hides a severe issue (Samantha: score 82, but savings run out at 73). In that case the subject reads "Something in your plan I want you to hear from me first". *Celebratory* for a strong band with nothing severe.
- **Topics** come from the plan: retirement depletion, cash cushion, negative cash flow, life cover, college gap, high-rate card, umbrella. The most severe are picked first. The first step is the plan's own recommendation that matches the main topic.
- **The advisor decides.** Tone and topics can be changed, the text can be edited, and the draft is approved by hand. Drafts and approvals are saved in the browser. **Nothing is sent**: once approved, the advisor copies the text into their usual channel.

## What is simulated

- No families. The four families and all their numbers come from `cases/`.
- The advisor ("David") and the top navigation copy the Sherpas product video. Only **Clients** works.
- The client page reproduces the layout of the Sherpas shared plan from the case data. The original plan stays one click away ("Open the shared plan in Sherpas").
